# `intent/` — 모든 기능 개발이 시작되는 곳

> 규칙 본문의 **SSOT 는 이 파일**입니다. 교육자료(`docs/education/`)와 `CLAUDE.md` 는
> 여기를 가리킬 뿐이고, 어긋나면 이 파일이 맞습니다.
>
> 출처: Anthropic [AI-Native SDLC playbook](https://claude.com/blog/the-ai-native-sdlc-playbook).
> 플레이북이 제안한 것은 `intent/` 폴더와 세 산출물까지이고, **폴더 내부 구조·승인
> 모델·방아쇠는 이 레포의 결정**입니다. 출처를 갈라 두는 이유는, 나중에 누가
> 「Anthropic 이 그렇게 하라고 했다」로 이 레포의 결정을 방어하지 못하게 하기 위해서입니다.

---

## 한 문장

**코드를 짜기 전에 「왜」를 남기고, 그 「왜」를 사람이 승인한 뒤에만 「무엇」과 「어떻게」로 내려간다.**

---

## 세 파일이 답하는 질문은 서로 다릅니다

| 파일 | 답하는 질문 | 초안 | **기본 승인** | 산출 브랜치 |
|---|---|---|---|---|
| `intent.md` | **왜** 이걸 하나 | 에이전트 | **동료 1인**(작성자 제외) | `intent/<slug>` |
| `spec.md` | **무엇을** 어떤 요구사항·설계로 | 에이전트 | **동료 1인**(작성자 제외) | `spec/<slug>` |
| `plan.md` | **어떻게** — 어느 파일을 어떤 순서로 | 에이전트 (plan mode) | **개발 담당자** (PR 없음) | `feature/<slug>` |

> ⚠️ **초안은 전부 에이전트가 씁니다. 사람은 전부 승인만 합니다.**
> 사람이 초안을 쓰면 속도의 이득이 사라지고, 사람이 승인을 안 하면 책임이 사라집니다.

---

## 승인 모델 — 리드는 «예외 판단자» 입니다

> 🔄 **2026-09-07 개정.** 초판은 「리드가 `intent.md`·`spec.md` 를 전부 승인한다」였고
> **폐기했습니다.** 리드가 그 판정을 실제로 내리는 경우가 드물다는 관찰 때문입니다.
> **항상 승인되는 승인은 승인이 아니라 서명**이고, 그것은 이 레포가 반복해 기록한
> 「공허한 검사는 초록과 구별되지 않는다」의 사람 버전입니다.

고칠 것은 리드의 주의력이 아니라, **판단이 필요한 소수를 나머지와 다르게 생기게 만드는 일**입니다.

* **기본**: 동료끼리 승인합니다. 리드는 안 봅니다.
* **예외**: 아래 **방아쇠 다섯** 중 하나가 걸리면 사람의 결정이 요구됩니다.

`intent.md` 를 동료끼리 승인하는 것은 **비용 절감이 아니라 품질 개선**입니다 —
「이 문제가 진짜인가」는 그 문제를 겪는 사람이 리드보다 잘 판단합니다.

## 방아쇠 — 다섯 개, 두 갈래

### 경로 축 (서버가 막습니다)

| # | 방아쇠 | 잡는 곳 | 오늘 상태 |
|---|---|---|---|
| **T1** | `migrations/` · `infra/` · 커널 핀 · 인증/RBAC · **게이트 자신**을 건드림 | `CODEOWNERS` | 🔴 **아직 게이트가 아님 — 아래 참조** |

> 🔴 **T1 은 오늘 «기록»이지 게이트가 아닙니다.** 실측: `require_code_owner_reviews: false`
> — `CODEOWNERS` 는 리뷰어를 자동 요청할 뿐 막지 않습니다. 그리고 **켤 수도 없습니다**:
> 협업자가 1명이고 GitHub 은 자기 PR 자기 승인을 금지하므로, 켜면 그 경로를
> **아무도 고칠 수 없게** 됩니다. 이 규모에서 CODEOWNERS 는 **원리적으로 게이트가
> 될 수 없습니다.**
>
> 진짜 강제는 **레인 시험**으로 갑니다 — `lane-check` 은 required 이고 관리자도
> 우회하지 못합니다. 그 검사는 아직 없습니다(`plan.md` §6).

`T1` 이 **게이트 자신**을 포함하는 이유: `githooks/` · `scripts/lane_check.py` ·
`delivered_test_run_baseline.json` · `.github/workflows/` · `CLAUDE.md` · `.claude/`.
**게이트를 고치는 권한은 그 게이트가 막는 것보다 셉니다.**

### 내용 축 (검사가 빨간 채로 남습니다)

| # | 방아쇠 | 왜 사람이어야 하나 | 초록이 되는 조건 |
|---|---|---|---|
| **T2** | 기준선에 **실패 이름이 추가됨** | **부채 등재** — 새 실패를 「알려진 것」으로 바꾸는 행위 | `spec.md` §4 에 `Debt-Accepted-By: <이름> — <사유>` |
| **T3** | `spec.md` §7 에 **답 없는 열린 질문** | 답 없이 설계가 확정되려는 것 | 각 질문 아래 `→ 답(<이름>): <내용>` |
| **T4** | `plan.md` §1 표에 **없는 파일**이 diff 에 있음 | 범위가 조용히 넓어짐 | 표에 추가하거나 `Scope-Extended-By: <이름> — <사유>` |
| **T5** | 변경 파일 수가 선언의 **2배 초과** | 다른 일이 딸려 들어옴 | T4 와 같음 |

> ⚠️ **방아쇠는 알림이 아닙니다.** 알림은 무시할 수 있고, 무시된 알림은 없는
> 알림과 같은 모양입니다. 그래서 이 축은 **아티팩트 안에 이름 붙은 결정이 적히기
> 전까지 검사가 초록이 되지 않는** 형태입니다. 이 레포의 17항목 자가점검이 이미
> 그 형태입니다 — 상태 뒤에 **사유**가 없으면 거부됩니다.

> ⚠️ **T2~T5 의 「이름」은 리드일 필요가 없습니다.** 요구하는 것은 **결정에 주인이
> 있다는 사실**입니다. 다만 T1 경로가 함께 걸리면 `CODEOWNERS` 가 리드를 세웁니다 —
> 두 축은 독립입니다.

판정 SSOT → `scripts/human_judgment_triggers.py`. 봉인 → `tests/test_human_judgment_is_recorded.py`.
T1 의 경로 목록은 **`CODEOWNERS` 에서 파생**합니다 — 하드코딩하면 두 곳이 갈라지고,
갈라지면 **서버가 막는 것과 검사가 말하는 것이 달라집니다.**

## 폴더 모양

```
intent/
├── README.md                  ← 지금 읽는 파일 (SSOT)
├── _templates/                ← 복사해서 쓰는 빈 서식
│   ├── intent.md
│   ├── spec.md
│   └── plan.md
└── <slug>/                    ← 의도 하나 = 폴더 하나
    ├── intent.md
    ├── spec.md
    └── plan.md
```

### 규칙 1 — 한 폴더에 세 파일, 각각 **하나씩만**

`spec.md` 가 둘 필요해 보이면 그것은 스펙을 쪼갤 신호가 아니라 **의도를 쪼갤 신호**입니다.

### 규칙 2 — 슬러그는 브랜치 이름이 됩니다

`intent/sample-retention/` → `intent/sample-retention` · `spec/sample-retention` ·
`feature/sample-retention`. 그래서 **영문 소문자·숫자·하이픈만** 씁니다.

### 규칙 3 — 언제 이걸 **안 써도 되나**

* 오탈자 · 문구 교체 · 명백한 버그 한 줄 → **그냥 고치세요.**
* 이미 승인된 `spec.md` 안에서의 후속 수정 → 같은 폴더의 `plan.md` 를 갱신.
* **새 기능 · 동작 변경 · 외부에 보이는 변화** → 반드시 `intent.md` 부터.

전부에 요구하면 형식이 되어 아무도 안 읽고, 아무것도 요구하지 않으면 의도가 사라집니다.

## 게이트 — 「지키자」가 아니라 「못 하게 한다」

| 층 | 어디서 도나 | 무엇을 막나 | 우회 |
|---|---|---|---|
| L0 `CLAUDE.md` | 세션 시작마다 | (막지 않음) 규칙을 에이전트에게 **도달**시킴 | — |
| L1 Claude Code `PreToolUse` 훅 | 동료 PC | 승인된 `plan.md` 없이 코드 파일 편집 | 설정 삭제 |
| L2 `githooks/pre-commit` | 커밋 시점 | intent 파일과 코드를 한 커밋에 섞는 것 | `--no-verify` |
| L3 `tests/test_*.py` → `lane_check` | pre-push + CI | 형식 위반 · **방아쇠 T2~T5** | `FCC_SKIP_LANE_CHECK=1` (로컬만) |
| L4 branch protection | GitHub 서버 | 승인 없는 `main` 착지 · `lane-check` red | **불가능** |
| — `CODEOWNERS` | (같은 자리) | 🔴 **오늘 아무것도 막지 않음** — 위 T1 주석 | 해당 없음 |

> 🔑 **L4 의 실제 값은 `.claude/contracts/branch-protection-declaration.json` 에 있고,
> `tests/test_documented_gate_values_match_the_live_config.py` 가 GitHub 실제
> 설정과 대조합니다.** 이 문서에 값을 다시 적지 마세요 — 사본은 갈라집니다.

> ⚠️ **L1~L3 은 실수 방지층이지 방어층이 아닙니다.** 셋 다 우회할 수 있습니다.
> **실제로 강제되는 것은 L4 하나뿐**입니다 — 서버에서 돌고 로컬 설정으로 못 끕니다.
> 이 문장이 사라지면 다음 사람이 L1~L3 을 강제라고 믿습니다.
>
> ⚠️ 그리고 **L3 은 CI 가 required check 일 때만 서버에서 강제됩니다.** 로컬
> `pre-push` 는 `FCC_SKIP_LANE_CHECK=1` 한 번이면 사라집니다.

L0~L3 의 진짜 역할은 「막는 것」이 아니라 **우회할 이유가 없게 만드는 것**입니다.
게이트가 오탐을 내면 사람들은 우회를 배우고, 그날부터 그 게이트는 0층입니다.

## 비개발자 동료를 위한 3단계

**① 의도 만들기** — 코드베이스를 몰라도 됩니다.

```
intent/_templates/intent.md 서식으로 새 intent 를 만들어줘.
문제는: (여기에 겪은 문제를 그냥 말로 쓰세요)
```

에이전트가 되물을 것입니다 — 누가 겪나, 해결되면 뭐가 달라지나, 제약은 뭔가.
끝나면 `intent/<slug>/intent.md` 와 PR 이 생깁니다. **여기서 멈추세요.**

**② 동료의 승인 기다리기** — 다른 동료 한 분이 PR 을 보고 머지하면 승인된 것입니다.
**자기 PR 은 자기가 승인할 수 없습니다.**

**③ 스펙 초안 요청** — 승인된 뒤에

```
intent/<슬러그>/intent.md 를 읽고 spec.md 초안을 만들어줘.
```

**코드는 여러분이 만들지 않습니다.** L1 훅이 코드 편집을 막습니다 — 실수하려 해도 못 합니다.

### 검사가 빨간색이면

화면에 **어떤 방아쇠가 왜 걸렸는지 이름으로** 나옵니다. 대개 셋 중 하나입니다.

* `T3` — `spec.md` §7 에 `→ 답( ):` 이 비어 있습니다. 답을 아는 사람에게 물어서 이름과 함께 적으세요.
* `T4` — `plan.md` 표에 없는 파일을 고쳤습니다. 표에 추가하거나, 왜 넓혔는지 적으세요.
* `T2` — 실패를 기준선에 넣으려 하고 있습니다. **이건 리드에게 물어야 합니다.**

## 상태(Status) 값

각 파일 머리말의 `Status:` 는 게이트가 읽는 **기계 판독 필드**입니다.

| 값 | 뜻 | 다음에 할 수 있는 것 |
|---|---|---|
| `draft` | 에이전트 초안. 승인 전 | PR 올리기 |
| `accepted` | 승인됨 (PR 머지 시 갱신) | 다음 단계 파일 만들기 |
| `superseded: <slug>` | 다른 의도로 대체됨 | 없음 (기록용) |
| `withdrawn` | 하지 않기로 결정 | 없음 (기록용) |

> `withdrawn` 과 `superseded` 를 **지우지 마세요.** 「하지 않기로 한 결정」도
> 결정이고, 지워지면 6개월 뒤 같은 제안이 다시 올라옵니다.
