# 시스템 명칭 — 확정과 후보군

작성: 2026-09-09 · 상태: **ZENITH 확정, 후보군은 열어 둠**

> 이 문서가 왜 있나. 이름은 코드가 아니라서 어디에도 안 적히면 **대화가 끝나는
> 순간 사라진다.** 실제로 오늘 「FCC Test Platform」을 바꾸기까지 후보를 여러 축
> 으로 훑었는데, 그 과정이 남는 곳이 없었다. 다음에 누가 「왜 ZENITH 인가」 또는
> 「다른 건 안 봤나」를 물으면 이 파일이 답한다.

---

## 왜 바꿨나

「**FCC** Test Platform」의 FCC 는 **규격 하나의 이름**이다. 그런데 이 플랫폼의
목적은 전 규격 대응이고, 오늘 시점에도 화면에는 FCC 아닌 것들이 이미 들어와 있다.
**이름이 제품의 범위를 실제보다 좁게 선언하고 있었다.**

⚠️ 그리고 이런 종류의 이름은 조용히 틀린다. 규격이 하나 늘어도 이름은 아무 알림을
보내지 않고, 어느 날 「FCC 플랫폼인데 왜 CE 가 있냐」는 질문이 사용자 쪽에서 온다.

---

## 확정 — ZENITH Test Platform

| | |
|---|---|
| **워드마크** | `ZENITH` (대문자 · 자간 0.12em) |
| **부제** | `Test Platform` |
| **뜻** | 천정(天頂) — 관측자 «바로 위»의 한 점. 별이 가장 높이 지나는 자리 |
| **글리프** | 대각으로 지나가는 유성 (별 + 자취 둘, 45°) |
| **적용** | `apps/web/src/locales/{en,ko}.json` → `routes.layout.appTitle` / `appKind` |

고른 이유는 두 가지다.

1. **규격 중립이다.** 어느 규격에도 속한 말이 아니라 이름이 범위를 좁히지 않는다.
2. **역할이 맞다.** 이 도구는 시험을 «하지» 않는다 — 시험이 어디까지 갔는지
   위에서 «본다». 대시보드가 편집기가 아니라 뷰어라는 것은 오늘 UI 작업 내내
   지킨 구분이고, 천정은 그 시점(視點) 자체를 가리키는 말이다.

⚠️ **철자 주의**: `ZENITH` 이고 `ZENIT` 이 아니다(후자는 독일어/러시아어 계열
표기이며 카메라 브랜드로 선점돼 있다).

## 후보군 — 아직 유효한 것들

확정을 뒤집자는 뜻이 아니라, **부제·모듈명·후속 제품 이름으로 재사용할 수 있는
어휘**로 남긴다. 이름 하나를 고르면 나머지가 버려지는 것이 보통인데, 이 저장소는
앞으로 이름 붙일 것이 더 있다(챔버 PC 에이전트 · 보고서 엔진 · 기준정보 서비스).

### ATTESTA — 🆕 2026-09-09 추가 (레포 소유자 제안)

| | |
|---|---|
| **어원** | 라틴어 `attestari` = 증언하다 · 입증하다 (`ad-` 향하여 + `testis` 증인) |
| **파생** | attest · attestation · testimony |
| **결** | 「측정한다」가 아니라 **「그것이 사실임을 증언한다」** |

**강한 점.** 이 제품이 최종적으로 만들어 내는 산출물이 성적서 —
즉 «적합함을 증언하는 문서»다. `attestation of conformity` 는 규격 세계에서
실제로 쓰이는 관용구이기도 하다. 이름이 «과정»(측정)이 아니라 «결과»(증언)를
가리킨다는 점에서 ZENITH 와 축이 다르고, 그래서 **서로 잡아먹지 않는다.**
ZENITH 가 「어디서 보는가」라면 ATTESTA 는 「무엇을 남기는가」다.

⚠️ **어원에 대한 정직한 단서.** 「test 와 어근이 같다」고 말하고 싶어지는데,
그것은 **정확하지 않다.** 영어 *test*(시험)는 라틴어 *testum*(금속을 시험하던
질그릇)에서 오고, *attest*는 *testis*(증인)에서 온다. 둘은 **다른 뿌리**다.
(*testis* 자체의 어원에는 학설이 갈리고, 일부는 *tri-* + *st-* 「제3자로 서
있는 자」로 본다.) 즉 「시험 + 증언」이 한 단어에 겹치는 것은 **어원이 아니라
말장난**이다 — 그래도 이름으로서는 좋은 말장난이고, 대외적으로 「어근이 같다」고
설명하지만 않으면 된다.

⚠️ **확인이 필요한 것**(이 문서를 쓰는 시점에 안 해 봤다):
- 상표. `Attesta` 는 짧고 라틴어 어간이라 선점 가능성이 낮지 않다.
  최소한 EUIPO/KIPRIS/USPTO 와 `.com` 을 봐야 한다.
- 발음 표기. 한국어로 「아테스타」인지 「어테스타」인지 — 사내 호칭이 갈리면
  이름의 이득이 절반 사라진다.

### 오늘 훑은 두 축

이름 후보는 대화에서 두 갈래로 나왔고, 그 **축 자체**가 재사용된다:

| 축 | 뜻하는 바 | 나온 이름 |
|---|---|---|
| **판정하는 자** | 규격에 비추어 합/부를 «가른다» | ARBITER · (라틴어 집정관 계열: CONSUL / PRAETOR) |
| **높은 곳에서 본다** | 전체를 «내려다본다», 판단은 사람이 한다 | **ZENITH**(확정) · APEX · MERIDIAN |
| **증언한다** 🆕 | 결과가 사실임을 «남긴다» | **ATTESTA** |

⚠️ 「판정하는 자」 축은 **일부러 고르지 않았다.** 이 시스템은 합/부를 스스로
정하지 않는다 — 사람이 정하고 시스템은 그것을 기록한다. ARBITER 라는 이름은
제품이 하지 않는 일을 약속한다.

### 참고 — 사용자의 기존 명명 관행

같은 사용자의 방사 측정 프로그램 이름이 **SPECTER** 다. 즉 이 조직의 명명 취향은
**「두 음절~세 음절 · 라틴/영어 실단어 · 전각 대문자 워드마크」**이고,
ZENITH·ATTESTA 둘 다 그 규칙 안에 있다. 새 이름을 지을 때 이 결을 벗어나면
같은 사람이 만든 도구로 안 보인다.

## 다음에 이름을 지을 때 재는 것

1. **규격 이름이 들어가 있나** → 있으면 탈락(그것이 이번에 바꾼 이유다)
2. **제품이 «하지 않는 일»을 약속하나** → ARBITER 가 걸린 지점
3. **철자가 하나로 정해지나** → ZENITH/ZENIT 처럼 갈리면 검색·상표가 새어 나간다
4. **한국어 호칭이 하나로 정해지나** → 사내에서 두 가지로 불리면 이름의 값이 반감
5. **상표·도메인** → 미확인 상태로 로고까지 만들지 않는다
