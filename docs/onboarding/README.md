# 팀 온보딩

> **이 폴더가 답하는 것**: 새로 합류한 사람이 (1) **자기 계측 프로그램을 provider 로
> 만들고**, (2) **이 플랫폼을 함께 개발하기** 위해 알아야 하는 전부.
>
> **이 폴더가 답하지 «않는» 것**: 이미 다른 문서가 소유한 것.
> 여기서는 **가리킵니다.** 같은 사실을 두 곳에 적으면 반드시 어긋나고,
> 어긋난 쪽을 읽은 사람이 틀린 것을 믿게 됩니다.

---

## 0. 두 종류의 독자

이 문서들은 **사람과 에이전트 둘 다**를 향해 씁니다. 실제 개발은 Claude Code 가
하기 때문입니다.

| 당신이 | 읽는 방식 |
|---|---|
| **사람** (시험원 · 기획 · 신규 개발자) | 위에서 아래로 읽습니다. 그림과 표가 그 용도입니다 |
| **Claude Code** (당신이 여는 세션) | 「이 파일을 읽고 시작해라」로 지시받습니다. 📋 복붙 블록이 그 용도입니다 |

⚠️ **그래서 이 문서들에는 「~하면 좋겠다」가 없습니다.** 에이전트에게 희망은 지시가
아닙니다. 모든 문장은 *무엇을 하라* 또는 *무엇이 참이다* 중 하나입니다.

## 1. 두 트랙 — 당신은 «둘 다» 합니다

```
                        당신
                    ┌────┴────┐
         트랙 A ────┘         └──── 트랙 B
    자기 프로그램의 provider 화        플랫폼 공동개발
                    │                     │
    당신의 비공개 레포              fcc-test-platform (public)
    측정 지식의 «주인»              분야 중립 규율의 «준수자»
```

| | 트랙 A — provider 화 | 트랙 B — 플랫폼 공동개발 |
|---|---|---|
| 어느 레포 | **당신 것** (비공개) | `fcc-test-platform` (public) |
| 무엇을 아나 | 이 분야에서 무엇이 유효한 시험인가 | 분야와 무관하게 참인 것만 |
| 산출물 | 계약 적합 · headless 이미지 · 챔버 노드 | PR |
| 실패하면 | 당신 분야만 안 붙는다 | **모두가 막힌다** |

⚠️ **가장 위험한 실수는 한쪽 습관을 다른 쪽에 가져가는 것입니다.**
필요한 파일을 옆에 복사해 두는 것은 트랙 A 에서는 자연스럽지만,
트랙 B 에서 계약 아티팩트를 복사하는 것은 **운영자가 2026-08-31 에 명시적으로
기각한 형태**입니다 (`90-known-traps.md` §1).

## 5. 이 문서들의 규율 — 당신이 고칠 때도 지켜야 합니다

이 저장소의 문서는 반복해서 **낡은 문장 때문에 잘못된 판정**을 낳았습니다.
그래서:

1. **수치에는 «측정일과 측정 방법»을 붙입니다.**
   「36 경로」가 아니라 「36 경로 (2026-09-07, `docs/api/headless-api.openapi.json` 의 `paths` 수)」.
2. **「~일 것이다」를 적지 않습니다.** 재지 않았으면 *재지 않았다*고 적습니다.
3. **같은 사실을 두 곳에 적지 않습니다.** 한 곳이 SSOT 이고 나머지는 가리킵니다.
4. **오늘 거짓인 문장을 발견하면 지우지 말고 «정정»으로 남깁니다.**
   다음 사람이 같은 문서를 읽고 같은 오판을 하는 것을 막는 것은 삭제가 아니라 기록입니다.

### ⚠️ 그리고 이 규율을 지켜도 낡습니다

`06-workspace-and-claude-md.md` **§4-a** 를 보십시오 —
**이 폴더의 한 문장이 «쓰이는 15분 사이에» 거짓이 된 사례**가 기록돼 있습니다.

**「없다」는 「있다」보다 빨리 낡습니다.** 없는 것은 누군가 만들면 되지만,
있는 것이 사라지려면 누군가 지워야 합니다.
