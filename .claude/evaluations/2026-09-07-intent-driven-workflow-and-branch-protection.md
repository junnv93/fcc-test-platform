# 의도 기반 개발 흐름 도입과 main 보호 — 2026-09-07

## Why

이 레인은 곧 **비개발자 동료들과 함께** 작업합니다. 동료는 전 작업을 Claude Code 로
수행합니다. 그 상황에 대해 이 레포는 준비되어 있지 않았고, 실측으로 구멍 셋이 나왔습니다.

**① 세션 시작 시 에이전트에게 도달하는 프로젝트 규칙이 0 이었다.**
`CLAUDE.md` 가 레인 루트·컨테이너 루트·`~/.claude/` 어디에도 없었습니다. 그리고
`.claude/rules/*.md` 셋은 **전부 `paths:` frontmatter** 를 가집니다 — 공식 문서는
*"Rules without a `paths` field are loaded unconditionally"* 라고 적으므로, 셋 다
**조건부**입니다. `supervisor-workflow.md`(81KB, 머지 위생)는 `.claude/**` 나
`scripts/supervisor_*.py` 를 만질 때만 로드되어, **평범한 기능 작업 세션은 그것을
한 글자도 보지 못했습니다.**

그 자리를 메운 것은 사용자 auto memory(토픽 98개 + 97줄 인덱스)였습니다. 그런데
auto memory 는 **기계-로컬이라 팀과 공유되지 않습니다** — 동료 PC 에서는 0 입니다.

> 모노레포 `CLAUDE.md` 는 이 함정을 **이미 알고** 대비했습니다:
> *"⚠️ 이 두 축은 `.claude/` 를 만지지 않는 세션의 커밋에도 발화하므로 여기 남긴다
> (rules 는 경로 스코프라 그때 로드되지 않는다)."*
> 이 레인은 갈라져 나오면서 규칙을 전부 `paths:` 뒤로 내렸고 그 대비 문장은
> 따라오지 않았습니다.

**② `main` 이 보호되지 않았다.** `404 Branch not protected`. 누구나 직접 push 가능.

**③ 「무엇을 왜 만드는가」가 남는 자리가 없었다.** 이 레인은 「어떻게 검사하는가」에
대해서는 성숙하지만(차단형 훅 3층·이름집합 게이트·평가 30건+), 그 앞단이 비어 있었습니다.

## What

* `intent/` 신설 — 운영 매뉴얼(SSOT)·서식 3종·첫 의도 삼종세트.
* `CLAUDE.md` 둘 — 레인 루트(137줄) + 컨테이너 루트(`fcc-delivery-final/`, git 아님).
* `CODEOWNERS` 신설 — 방아쇠 T1 의 SSOT.
* `main` branch protection **적용** (운영자 승인).
* 협업자 교육 문서 1건.

### 승인 모델 — 초판을 폐기하고 «예외 승인» 으로

초판은 「리드가 `intent.md`·`spec.md` 를 전부 승인」이었습니다. **리드 본인의 관찰로
폐기**했습니다 — *"내가 판단하는 경우는 극히 드문데"*.

**항상 승인되는 승인은 승인이 아니라 서명**이고, 그것은 이 레포가 반복해 기록한
**「공허한 검사는 초록과 구별되지 않는다」의 사람 버전**입니다. 고칠 것은 리드의
주의력이 아니라, **판단이 필요한 소수를 나머지와 다르게 생기게 만드는 일**입니다.

기본은 동료 1인(작성자 제외) 승인이고, 방아쇠 다섯이 걸릴 때만 사람의 결정이 요구됩니다:

| # | 방아쇠 | 초록이 되는 조건 |
|---|---|---|
| T1 | 되돌릴 수 없는 경로 + **게이트 자신** | `CODEOWNERS` — 🔴 **오늘 게이트가 아니다**(§정정 ④) |
| T2 | 기준선에 실패 이름 추가 | `Debt-Accepted-By: <이름> — <사유>` |
| T3 | 답 없는 열린 질문 | `→ 답(<이름>): <내용>` |
| T4 | `plan.md` 표에 없는 파일 | 표 추가 또는 `Scope-Extended-By:` |
| T5 | 선언 대비 2배 초과 변경 | T4 와 같음 |

**핵심**: 방아쇠는 **알림이 아니라 red** 입니다. 알림은 무시되면 없는 알림과 같은
모양이라, 아티팩트 안에 **이름 붙은 결정**이 적히기 전까지 검사가 초록이 되지 않는
형태로 만듭니다 — 이 레포의 17항목 자가점검이 이미 그 형태입니다.

## How

`CODEOWNERS` 는 T1 경로 목록의 **SSOT** 이고, `scripts/human_judgment_triggers.py`(미구현)
가 그것을 **파싱**합니다. 하드코딩하면 「서버가 막는 것」과 「검사가 말하는 것」이 갈라집니다.

### branch protection 적용값과 그 값이어야 하는 이유

> 🔑 **값과 근거의 SSOT 는 `.claude/contracts/branch-protection-declaration.json`**
> 이고, `tests/test_documented_gate_values_match_the_live_config.py` 가 그것을
> GitHub 실제 설정과 대조합니다. 아래 표는 그 뒤에 쓰인 «요약»이고, 어긋나면
> 검사가 말합니다.

| 값 | 설정 | 왜 |
|---|---|---|
| PR 필수 | 켬 | 실측: 최근 50개 착지 **전부 PR 머지**, 직접 push **0건**(`--first-parent`) |
| 필수 검사 | `lane-check` | 실측한 check run **이름**. 워크플로 이름(`checks`)이 아니다 |
| 필수 승인 수 | **0** | 협업자 **1명** + GitHub 은 자기 PR 자기 승인 금지. 1이면 모든 머지가 `--admin` 을 요구하고, 그것을 형제 세션 6개에 통보 없이 강제하게 된다 |
| `strict` | **끔** | 아래 §정정 |
| `required_linear_history` | **끔** | **no-squash 규칙이 머지 커밋을 쓴다** — 켜면 전부 막힌다 |
| `enforce_admins` | **켬** | 아래 §정정 ③ |
| force push · 삭제 | 금지 **(`main` 에만)** | 기능 브랜치 삭제는 그대로 된다 |

### ⚠️ 주입 검증되지 «않은» 것

**직접 push 차단은 실증하지 않았습니다.** 이유: 만약 통과해 버리면 force push 가
방금 금지돼 **치울 수 없습니다.** 첫 실증은 다음 세션의 push 에서 나옵니다.
「선언을 되읽었다」와 「막는 것을 봤다」는 다른 명제이고, 여기서는 전자만 참입니다.

## §정정 — 이 세션이 «다섯 번» 틀렸다

형제 세션 셋(`-97`·`-e8`·`-4a`)이 지적했고 **전부 자체 실측으로 확인**했습니다.

**① `strict=false` 의 근거가 거짓이었다.** 초판 통지문은 *"`merge_readiness_guard.py`
가 더 나은 술어로 이미 하고 있어서"* 라고 적었습니다. 실측:
`githooks/pre-push:33` 이 `advise || true` 로 부르고, `merge_readiness_guard.py:390`
은 경고를 찍은 **직후 `return 0`** 합니다. `merge <N>` 하위명령은 `.github/workflows/`
에서 **참조 0건** — 사람이 고르면 도는 관례입니다. **차단하지 않습니다.**

참 근거는 다른 것이었습니다: **`lane-check` 이 PR 헤드가 아니라 «합친 트리»를
검사합니다.** `checks.yml` 이 `pull_request` 로 걸리고 `checkout@v4` 에 `ref:` 가
없어 `refs/pull/N/merge` 가 체크아웃됩니다. 실증(run 34067524062):
`HEAD is now at 378ea31 Merge f88193fe… into 6e1fcb26…`.
즉 필수 검사가 이미 「합치면 초록인가」를 묻습니다.

**⑤ 🔴 「그 구멍은 관측된 적 없다」고 적은 것이 거짓이었다** (2026-09-07 추가).

앞 판은 *"#137·#138 은 그때의 최신 main 과 합쳐 검사했으므로 반례가 아니다"* 라고
적었습니다. **틀렸습니다. #137 은 낡은 초록 위에서 머지됐습니다:**

```
검사한 base     ae7d7d4     (마지막 lane-check 이 합친 것)
머지 시점 main  d340506     (머지 커밋 6e1fcb2 의 «첫 부모»)
그 사이         PR #139 · #136 — 5 커밋
겹침            0 건        (PR API 파일 목록 30 ∩ 그 사이 4)
```

정확한 문장: **「낡은 초록으로 머지됐다」의 사례이지 「낡은 초록 때문에 깨졌다」의
사례가 아니다.**

⚠️ **틀린 이유가 더 중요합니다.** `gh run view --log | grep "HEAD is now at"` 는
«마지막 실행»을 보고, GitHub 은 실행마다 머지 ref 를 **다시 계산**합니다 —
그래서 그 방법은 **언제나** 「최신과 합쳤다」로 답하고 **이 기제를 영원히 못 봅니다.**
비교할 두 수는 **검사한 base** 와 **머지 커밋의 첫 부모**입니다.

**도구가 답한 것이 내가 물은 것이 아니었습니다.** 형제 세션 `fcc-delivery-final-4a`
가 잡았습니다.

**남는 구멍**: GitHub 은 base 가 움직여도 검사를 **다시 돌리지 않습니다.** 기록된
SUCCESS 는 «그때의» base 에 대한 것입니다. 실제 사례 둘 — PR #137 은 `CLEAN` 인 채로
main 이 네 번 움직였고 그중 #138 이 같은 두 파일에 의미상 겹치는 변경을 넣었습니다.
PR #138 은 `85c43a4` 기준 초록을 받았고 머지 시점 main 은 `dc9fdf9` 였습니다.
**이 위험을 감수합니다 — 다만 감수한다고 적습니다.**

**③ `enforce_admins=false` 의 사유가 성립하지 않았고, 그래서 통지문의 «보장»이
거짓이었다.** 초판은 「승인 수 0 과 같은 이유(자기 PR 자기 승인)」로 껐습니다.
그런데 **필수 승인 수가 0이면 자기 승인 문제가 애초에 안 생깁니다.** 끈 실제 효과는
**「관리자는 필수 검사 `lane-check` 도 우회할 수 있다」** 였고, 협업자가 1명이며
그가 관리자이므로 제가 6개 세션에 보낸 *"lane-check 이 red 면 서버에서 머지가
막힙니다"* 는 **오늘 거짓**이었습니다. → **설정을 고쳐 문장을 참으로 만들었습니다**
(`enforce_admins: true`, POST 로 활성화 — PATCH 는 404 다).

탈출구는 관리자가 protection 자체를 고치는 것뿐이고, 그것은 **per-머지 무음 우회가
아니라 의도적·기록되는 행위**입니다. 이 레포가 우회 환경변수를 일부러 시끄럽게 만든
것과 같은 형태입니다.

**④ 🔴 `CODEOWNERS` 를 「경로 축 게이트」로 적은 것이 거짓이었다.** 실측:
`require_code_owner_reviews: false` — CODEOWNERS 는 **리뷰어 자동 요청**만 합니다.
그리고 **켤 수도 없습니다**: 협업자가 1명이고 GitHub 은 자기 PR 자기 승인을 금지하므로
켜면 그 경로를 **아무도 고칠 수 없게** 됩니다. 이 규모에서 CODEOWNERS 는
**원리적으로 게이트가 될 수 없습니다.**

⚠️ 그리고 이것이 **30분 전 `enforce_admins` 에서 고친 것과 같은 계급**입니다 —
「이름이 보장처럼 생겼는데 보장이 아닌」 형태. 그 결함을 고친 직후 같은 결함을
다시 만들었습니다. 하필 이름 지어진 것이 **게이트 자신**이라 더 위험했습니다.

→ CODEOWNERS 를 **남기되 파일 머리에 「게이트가 아니다」를 적었습니다.**
진짜 강제는 **레인 시험**으로 갑니다(`lane-check` 은 required 이고 관리자도 우회 못 함).
그 검사는 아직 없고 `spec.md` §7-5 가 그 열린 질문입니다.

**② 「브랜치 삭제 금지」의 범위를 안 적었다.** `allow_deletions: false` 는 **보호
패턴(`main`)에만** 걸립니다. 기능 브랜치에는 규칙이 **0개**이고, 형제 세션이 보호가
켜진 뒤 머지된 기능 브랜치 둘을 실제로 삭제했습니다. 「삭제가 막혔다」로 전달되면
머지 뒤 정리를 안 하게 되어 원격에 브랜치가 쌓입니다.

> **왜 이것을 남기나.** 결정(`strict=false`)은 둘 다 살아남았고 **근거만** 바뀌었습니다.
> 근거가 거짓이면 결정이 옳아도 다음 사람이 그 거짓 위에 쌓습니다.
