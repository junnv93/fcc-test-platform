# 어두운 주황은 존재하지 않는다 — 그리고 그것을 네 번 튜닝으로 고치려 했다

> 2026-09-08 실측. base `origin/main@5fdec3f`, 브랜치 `feature/flowdeck-console-ui`.
> 리그: Windows 11 · Node 22.20 · `apps/web` 로컬 dev(:5174) · Keycloak 25(:8081)
> · platform API(:8002, 호스트 venv) · PostgreSQL 15(:5433).
> ⚠️ contracts 핀은 선언 그대로(`v0.1.26` / `kernel-v0.5.4`).

## Why — 홈이 「지금 무엇이 문제인가」에 답하지 않았다

기존 홈(`overview.tsx`)이 주는 것은 바로가기 셋과 「진행 중인 측정」 목록 하나였다.
시험원이 그 질문에 답하려면 `/chambers` · `/progress` · `/sessions` 를 차례로 열어야
했고, 열어도 「어제와 비교해 나빠졌는가」는 어디에도 없었다.

작업은 참고 디자인(`flowdeck.html`, 자동화 run console)을 이 도메인으로 옮기는
형태로 진행했다. 그 과정에서 **디자인 결정보다 «틀린 전제»를 찾는 데 시간이 더
들었고**, 이 문서는 그 전제들을 남긴다.

## What — 값을 치른 것 다섯

### ① 어두운 주황은 존재하지 않는다 (네 번 시도, 전부 실패)

밴드 3분류(Unlicensed / Licensed / mmWave)에 색을 주고 그 색으로 넓은 면(행 배경)을
칠했다. 파랑·보라는 어두운 배경에서도 파랑·보라로 남았는데 **주황만 갈색으로
죽었다.** 고치려 한 순서와 결과:

| # | 시도 | 결과 |
|---|---|---|
| 1 | 채도를 0.16 → 0.105 로 낮춤 | 두 테마 모두 «흐리멍덩» |
| 2 | OKLCH 색상 68 → 52 (노랑-연두 → 주황) | 여전히 벽돌색 |
| 3 | sRGB → oklab 보간 (중간이 탁해지는 것 회피) | 개선되나 미해결 |
| 4 | 면 전용 파생색(`--band-*-fill`, L 0.42) | **더 나빠짐** — L 0.42 주황 = 갈색 |
| 5 | **색상을 틸(178)로 교체** | 한 번에 해결 |

⚠️ **네 번은 튜닝이었고 다섯 번째만 문제를 다시 정의했다.** 주황은 높은 명도에서만
주황이고, 「어두운 주황」이라는 것은 색으로서 존재하지 않는다. 그것은 파라미터로
못 고치는 색 자체의 성질이다. 파랑·보라에는 없는 이 비대칭이 «한 팔레트를 세 색에
같은 규칙으로 적용»하는 접근을 무너뜨렸다.

남은 규칙: **색은 «작은 면적에 온전한 밝기»로, 넓은 면은 틴트로.** 행 하단 3px 바가
색을 나르고 행 배경은 길이만 말한다.

### ② 라이트 테마에서 카드와 페이지가 같은 흰색이었다

`--c-card-surface: var(--surface-bg)` 이고 `--p-light-surface-bg: #ffffff` 였다. 즉
카드와 페이지가 **같은 값**이고 `--elevation-0`(그림자 없음)이라, 둘을 나누는 것이
1px 테두리뿐이었다. 거기에 `.app-shell` 의 accent 14% 라디얼 글로우가 흰 배경 위에
라벤더 안개로 깔렸다.

다크는 처음부터 옳았다(`#111420` 페이지 / `#181c2a` 카드). **라이트만 관계가 반대로
적혀 있었다.** base = 페이지 / alt = 카드로 바로잡고 글로우를 14% → 5% 로 내렸다.

⚠️ 이 교정이 상태 뱃지 5색의 합성 대비를 4.5:1 아래로 끌어내렸고(3.99~4.12),
`design-token-conformance` 가 즉시 잡았다. 색상은 유지한 채 명도만 내려 재계산했다
(§Verification).

### ③ 비율 정렬이 «비교하려고 만든 토글»을 방해했다

계열·모드를 「나쁜 것 위로」(비율 오름차순) 정렬했다. 규칙 자체는 좋지만, 모델
토글을 누르면 비율이 바뀌고 따라서 **행이 통째로 뛰었다.** 848U 에서 보던 U-NII 가
840 에서는 세 칸 아래에 있으니 눈이 매번 다시 찾아야 했다.

정렬을 «이름»으로 고정했다. 늦었다는 사실은 위치가 아니라 막대 길이와 색이 말하고,
그 둘은 필터가 바뀌어도 같은 자리에서 변한다.

### ④ 계층이 셋인데 계획 테이블의 칸은 둘이다

대분류 → 계열 → 모드가 필요한데 `published_plan_expectation` 이 내주는 것은
`progress_bucket_id` 와 `progress_area` 둘뿐이다. 지금은 `progress_bucket_id` 가
`"Unlicensed band / U-NII"` 로 두 층을 담고 UI 가 약속된 구분자로 나눈다.

⚠️ **이것은 임시다.** UI 가 이름을 보고 «추측»하는 것과는 다르다 — 두 사실 모두
계획이 운반하고 UI 는 디코드만 한다. 그래도 정식으로는 계열이 자기 컬럼을 가져야
하고, 그때 `SEP` 한 줄이 사라진다. 구분자에 의존하는 코드를 한 곳에 모아 둔 이유가
그것이다.

### ⑤ 「never faked from partial aggregates」를 새 화면이 뒤집을 뻔했다

콘솔 레이아웃은 지표 타일 세 개를 부른다. 세 번째 자리에 실패율을 넣으려면 도달
가능한 부분 집계에서 계산해야 하는데, `overview.tsx` 가 이미 그것을 거부하는 판정을
갖고 있었다:

> *"Deliberately NOT shown (G3 — require backend read contracts): … 내 실패 N건 …
> They appear only after a contract phase, **never faked from partial aggregates**."*

⚠️ 인용한 `§3 데이터 등급표` 는 **이 저장소 어디에도 없다**(실측: `git grep` 0건).
문서가 없는 절을 가리키고 있지만 판정 자체는 유효하므로 따랐다.

타일을 두 형태로 나눴다 — 측정된 값을 가진 것, 또는 「이 값을 주는 읽기 계약이 아직
없다」를 그 자리에 적는 것(`StatTile` 의 `unavailable`). 계약이 생기는 날 타일이 값을
얻고 화면의 나머지는 그대로다.

## How — 무엇을 만들었나

**세 라우트, 한 컴포넌트.** 같은 막대가 시험원과 PM 에게 다른 뜻이 되면 두 사람이 같은
화면을 보며 다른 말을 한다. 그래서 `scope` 가 패널을 «고르기»만 한다.

| 라우트 | 목적 | 답하지 않는 것 |
|---|---|---|
| `/` | 시험원 — 남은 case · 기술별 진행 · 부적합 | 일정·원가 |
| `/programme` | PM — 진행 점검 + 고객사 보고(모델 단위) | 무엇을 지금 측정할지 |
| `/combined` | 관리자 — 위 둘의 어긋남 | (여기만의 위젯을 두지 않는다) |

세 파일 상단에 「누가 / 언제 / 무엇에 답하나 / 답하지 않는 것」 박스를 박았다.

**신규 UI 프리미티브 6종** — `StatTile`(계약 없음 상태를 1급으로) · `HealthBars`
(`forceTone`: 진행률은 건강도가 아니다) · `TrendChart` · `ChamberCard`(챔버는 행이
아니라 방) · `DonutProgress` · `ProgressRings`(단일 링, 밴드가 전체 중 기여도만큼 채움).

**팔레트 노브** — 색을 리터럴로 흩뿌리지 않고 OKLCH 세 축으로 분해했다.

    --band-chroma / --band-hue-{unlicensed,licensed,mmwave} / --band-lightness
    --band-tint-lightness (테마마다 «반대» — 다크는 밝은 틴트, 라이트는 어두운 틴트)
    --gauge-tint / --gauge-track-mix / --gauge-track-base / --gauge-row-gap
    --ring-size / --ring-track-mix / --ring-figure-size

⚠️ 명도는 테마별로 «선언»하고 색상·채도는 공유한다. 초기에 다크 값을 `calc(1 - l)` 로
뒤집어 라이트를 파생시켰는데 탁해졌다 — OKLCH 에서 C 는 절대값이라 L 이 내려가면 같은
C 가 훨씬 덜 선명해 보인다.

**이슈 트래커 ⇄ 진행률 양방향 연결.** 모드별로 묶고(같은 모드 두 줄이 목록만 늘렸다),
어느 쪽에 올려도 반대쪽이 켜지고, 클릭하면 고정되며 화면 밖이면 스크롤한다.
⚠️ 호버에는 스크롤하지 않는다 — 목록을 훑는 동안 좌측이 움직이면 커서 아래 행이
저절로 바뀐다.

**Export 는 목업이다.** 고객사 보고서에 무엇이 들어갈지 PM 팀과 정해지지 않았고, 버튼이
그 미정 넷(형식·범위·깊이·증적)을 스스로 펼친다. 되는 척하는 죽은 버튼을 두지 않기
위해서다.

## 후속 — 남은 것과 그 이유

1. **`progress_family` 컬럼** — 임시 구분자를 걷어낸다. 마이그레이션 → 어댑터 SQL →
   엔벨로프 → OpenAPI 재생성 → codegen 순서이며, 그 사슬 때문에 이번엔 미뤘다.
2. **테스트 3종** — `console-home.spec.ts`(§2 판정), `tests/ui/` 렌더 4건(배럴 관례),
   `web-font-loading` 확장(self-host 폰트 2종).
3. **번들 예산 재측정** — 폰트 2종이 실렸으므로 `measure:bundle` 후
   `bundle-budget.json` 의 `measuredGzipBytes` 갱신. 계수는 손대지 않는다.
4. **시각 골든 재생성** — 전부 바뀐다. ⚠️ 교체는 검사를 끄는 것과 형태가 같으므로
   전후를 사람이 눈으로 대조한 뒤에만.
5. **시험원 홈(`/`)** — 아직 이전 레이아웃이다. PM 화면에서 세운 언어로 맞춰야 한다.
6. **spec §7 열린 질문 넷** — `→ 답( ):` 이 비어 있어 방아쇠 T3 가 발화 중이다.
   코드보다 먼저 사람의 답이 적혀야 한다.

## 부기 — 참고 디자인에서 «옮기지 않은» 것

`flowdeck.html` 의 커맨드 팔레트는 `<div class="scrim" hidden>` 인데 `.scrim { display: grid }`
가 `[hidden]` 을 덮어써 **열린 채로 고정돼 있었다**(실측). 그래서 `plan.md §2` 는
팔레트 검사를 「열린다」가 아니라 **「닫힌다」**로 적었다. 참고물의 결함을 함께
옮기지 않으려면 재는 축이 반대여야 한다.
