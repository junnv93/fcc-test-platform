# 선언과 실측을 손으로 맞추던 자리 셋을 파생으로 바꾼다 (2026-09-05)

## Why

이 저장소는 같은 계급의 결함을 반복해 값으로 치렀고, **그 역사가 이미 두 군데에 적혀
있었다 — 그런데 그것을 재는 검사는 0건이었다.**

`pyproject.toml` `[project.optional-dependencies]` 주석:

> `jsonschema` 와 `PyJWT[crypto]` 는 검사가 **실제로 임포트** 하는데 선언에 없었다.
> 이 머신에는 이미 깔려 있어 로컬은 초록이었고, 갓 클론한 CI 러너에서만 드러났다.

같은 파일 `[tool.setuptools.package-data]` 주석:

> `decision_catalogue.json` 이 빠진 배포물은 설치도 되고 휠도 만들어지지만 **import 하는
> 순간 죽는다**. … 상자에는 실려 있고 **휠에만 없었다**.

두 문장은 **같은 결함의 두 얼굴**이다: 「코드가 실제로 필요로 하는 것」과 「배포 선언이
말하는 것」이 손으로 동기화된다. 손 동기화는 반드시 낡는다.

그리고 2026-09-04 에 그 계급이 두 번 더 나왔다.

* `tests/test_central_docker_compose.py` 가 `yaml` 을 가드 없이 부르는데 `PyYAML` 이
  어느 extra 에도 없었다 → **중앙 저장소 lane-check CI 가 24건 빨간 채로 굳어 있었다**
  (run 33858657216). 직전 배송은 자기 회귀가 0건임을 증명하려고 main 의 실패 집합과
  **손으로 대조**해야 했다. 다음 사람은 그렇게 하지 않는다.
* PM/RF 엑셀 서식이 패키지 밖에 있어 휠에 실리지 않았다 → 컨테이너에서 내보내기가
  **구조적으로** 불가능했다. 개발 트리에서는 전부 초록이었다.

세 번째 자리도 같은 형태다. 중앙 DB 의 DDL 은 두 경로로 생기는데(생성되는 `001`,
손으로 쓰는 증분 마이그레이션) **둘을 대조하는 검사가 0건**이었다. 실측: `034` 는
`idx_sample_custody_events_project_cert` 를 부분 인덱스로 만드는데 스키마 선언이 그것을
말하지 않아 `001` 은 전체 인덱스로 나왔다.

## What

세 자리 전부 **파생 대조**로 바꿨다. 선언을 손으로 세는 대신 두 집합을 뽑아 비교한다.

### ① 의존성 폐포 — `tests/test_supply_closure_axis.py`

가드 없이 import 하는 서드파티 이름을 AST 로 뽑고, 그것이 `pyproject.toml` 이 선언한
배포판으로 덮이는지 본다. 이름 매핑(`yaml` → `PyYAML`)은 **하드코딩하지 않는다** —
표준 라이브러리의 `importlib.metadata.packages_distributions()` 가 그 SSOT 다
(공식 문서가 그 함수의 반환 예시로 `{'yaml': ['PyYAML']}` 을 든다).

두 결함 계급을 **나눠서** 보고한다. 고치는 사람도, 고치는 법도 다르기 때문이다.

| | 계급 A | 계급 B |
|---|---|---|
| 무엇 | 이름은 해소되는데 선언에 없다 | 이름이 어디에서도 해소되지 않는다 |
| 뜻 | 우연히 깔린 것에 기대고 있다 | 이 상자에 없는 코드를 부른다 |
| 고침 | `pyproject.toml` 에 선언 | 협력자가 어느 레인에 사는지 판정 |

### ② 패키지 자원 폐포 — 같은 파일

**실제로 휠을 빌드해서** 잰다. 선언(`package-data` 글롭)을 읽어 재면 그 선언이 틀렸을
때 검사도 같이 틀린다 — `decision_catalogue.json` 과 엑셀 서식이 정확히 그렇게 빠졌다.
재는 대상은 선언이 아니라 **산출물**이어야 한다.

⚠️ 빌드는 트리 밖 사본에서 한다. non-editable 설치는 `build/` 를 남기고 `lane_check` 은
그 트리에서 **판정을 거부한다**. 검사가 자기가 재는 트리를 오염시키면 그 측정은 자기
부작용을 잰다.

### ③ 마이그레이션 ↔ 스키마 인덱스 정합 — `tests/test_migration_index_parity_axis.py`

증분 마이그레이션이 만드는 모든 인덱스를, 스키마 SSOT 에서 생성기가 내는 정본 DDL 과
대조한다. 허용하는 차이는 둘뿐이고 **둘 다 「무엇을 만드는가」가 아니라 「어떻게
적용되는가」**다: `CONCURRENTLY`(운영 DB 는 쓰기를 막지 않는다) 와 `IF NOT EXISTS`
(`001` 은 재실행될 수 있고 증분은 원장이 한 번만 적용한다).

## How

**선언을 고친 것이 아니라 선언이 표현할 수 있는 것을 쓴 것이다.** 생성기는 `where`
(부분 인덱스)·`orders`(정렬)·`using`·`expressions` 를 **이미 지원하고 있었다** —
스키마 JSON 이 그것을 쓰지 않았을 뿐이다. 도구가 부족했던 게 아니라 대조가 없었다.

`test_central_docker_compose.py` 는 같은 의존성을 두 방식으로 동시에 잘못 다루고
있었다: 네 개의 지역 `import yaml` 중 셋은 `except: skipTest` 가드를 달아 **컨테이너
보안 불변식(네트워크 격리·권한 드롭·신뢰 홉·빌드 대상 파생)을 스스로 껐고**, 나머지
하나는 가드가 없어 러너를 세웠다. 답은 가드를 늘리는 것이 아니라 **선언을 채우는
것**이다 — 이 저장소의 `lane_check` 이 같은 형태를 이미 이름 붙여 거부한다:
*"기준선을 관측값으로 덮어써서 초록을 만들지 마라 — 그것은 검사를 끄는 것이다."*

`selenium` 은 `browser-qa`, 계약 레인의 `psycopg` 는 `live-postgres` 로 **전용 extra**
에 선언했다. 중앙 이미지의 의존성 집합에 밀어 넣지 않으면서도 「무엇이 필요한가」는
적힌다. 선언하지 않으면 *"돌려보니 죽더라"* 가 유일한 발견 경로가 된다.

### 계급 B 는 원장이지 예외 목록이 아니다

운영자 판정(2026-09-05)으로 계급 B 의 유일한 항목은 이번 범위 밖이다. 그것을
`skip` 으로 끄지 않고 **양방향 원장**으로 뒀다 — 이 저장소의 `lane_check` 이 쓰는 것과
같은 형태다. 늘어나도 red, **해소돼도 red**(*"선언이 낡았다는 사실이고, 그것도
소식이다"*). 예외 목록은 한 방향으로만 자라 조용히 낡지만 원장은 낡을 수 없다.

**되돌려 확인했다.** 통과만 하는 시험은 아무것도 지키지 않는다.

| 변이 | 결과 |
|---|---|
| 원장에 없는 해소 불가 import 를 새로 만든다 | `[새로 생김]` 으로 red |
| 원장에 이미 해소되는 이름을 넣는다 | `[해소됨]` 으로 red |
| `PyYAML` 선언을 되돌린다 | 계급 A 로 red, 부르는 줄까지 이름 |
| 인덱스 술어의 인용을 어긋나게 둔다 | 정합 게이트가 두 정의를 나란히 놓고 red |

**CI 조건 재현** — `git ls-files` 로 추적 파일만 복사한 트리에 `pip install -e '.[test]'`
(워크플로와 같은 명령)를 하고 돌렸다: `PyYAML 6.0.3` 이 설치되고
`test_central_docker_compose.py` 의 **24건이 전부 통과**한다(게이트 2개 포함 95건).

**lane_check** — platform 선언 0 == 관측 0, 계약 선언 29 == 관측 29. 양쪽 다
`--write-baseline` 없이.

**성능** — AST 스캔이 390 파일·3,316 import·약 1.5초다. 시험마다 다시 돌리면 그 값을
시험 수만큼 낸다. 게이트가 느리면 사람이 게이트를 건너뛰기 시작하므로 클래스당 한 번만
돌게 했다(6.87s → 5.01s). 휠 빌드는 격리 없는 경로를 먼저 시도해 네트워크를 타지 않는다.

  작업으로 미뤘다**(운영자 판정 2026-09-05). 원장이 그것을 잊지 않는다.
